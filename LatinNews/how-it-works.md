# Как работает эта програма

Разбор принципа работы новостной ленты, чтобы можно было повторить такое самостоятельно.

---

## 1. Общая схема

```
main.jsx
  └── App.jsx          ← вся логика и состояние
        ├── Header          (статическая шапка)
        └── PostList        (список → .map())
              └── PostCard  (одна карточка)
```

Главный принцип: **состояние живёт в App, компоненты получают данные через props.**

Ничего не хранится в localStorage / Redux / контексте — только `useState` в одном компоненте и один `useEffect` для загрузки данных.

---

## 2. Состояние App — самое важное

```jsx
const [posts, setPosts] = useState([])            // все посты с сервера
const [isLoading, setIsLoading] = useState(true)  // идёт ли загрузка
const [error, setError] = useState('')             // текст ошибки ('' = нет ошибки)
```

Правила, из которых всё следует:

1. **`''` / пустой массив = «ничего не произошло».** По этому код рендеринга пишет сам: `if (isLoading) ...`, `if (error) ...`.
2. **Пустой список — не ошибка.** Если пришли данные, но массив пуст, `PostList` просто покажет «Ничего не найдено».

---

## 3. Загрузка данных (единственный useEffect)

```jsx
useEffect(() => {
    fetch('https://jsonplaceholder.typicode.com/todos')
    .then(response => {
      if (!response.ok) throw new Error('Ошибка загрузки') // HTTP 404/500
      return response.json()
    })
    .then(data => setPosts(data))          // успех → данные в состояние
    .catch(() => setError('Не удалось...'))// провал → текст ошибки
    .finally(() => setIsLoading(false))    // всегда → убрать спиннер
}, [])
```

Как читать цепочку:

- `fetch` возвращает промис; `.then` выполняется после ответа.
- **Пустой массив зависимостей `[]`** — эффект запускается один раз при монтировании.
- `response.ok` — сам `fetch` не считает 404/500 ошибкой, проверять нужно руками.
- `catch` ловит и сетевую ошибку, и наш `throw`.
- `finally` выставляет `isLoading = false` в любом исходе — иначе вечная «Загрузка...».

Пока `isLoading === true`, компонент делает ранний выход:

```jsx
if (isLoading) return <p>Загрузка новостей...</p>
```

Это называется **условный рендеринг**: ветка JSX выбирается по состоянию.

Почему именно `useEffect`, а не просто `fetch(...)` в теле компонента: тело выполняется **на каждый рендер**, и без эффекта запрос ушёл бы десятки раз (при каждом обновлении состояния). `useEffect(..., [])` выполняет код один раз — после первой отрисовки.

---

## 4. Список и карточки (.map)

```jsx
// PostList
{posts.map(post => (
  <PostCard key={post.id} post={post} />
))}
```

- `.map()` превращает массив данных в массив JSX.
- **`key` обязателен** — по нему React понимает, какой элемент какой: без него (или с неуникальным) список будет «прыгать» и терять состояние.
- Пустой список — отдельное сообщение «Ничего не найдено».

Цепочка пропсов:

```
App (state) → PostList (массив) → PostCard (один пост)
```

`PostCard` ничего не знает про остальные — только свой `post`. Вся логика (загрузка, обработка ошибок) остаётся в `App`, карточка только рисует.

---

## 5. Стили

- Палитра — CSS-переменные в `:root` (`src/index.css`): `var(--Purple)` и т.д. Цвета нигде не дублируются хардкодом.
- Сетка карточек: `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))` — сама подстраивается под ширину.
- Автор прижат к низу карточки: у футера `margin-top: auto` при `display: flex; flex-direction: column` у самой карточки.
- Адаптив: `@media (max-width: 600px)` — одна колонка.
- Скрытие полосы прокрутки: `scrollbar-width: none` (Firefox/Chrome) + `::-webkit-scrollbar { display: none }` (Safari/старый Chrome). Прокрутка при этом работает.
- Длинные слова страхует `overflow-wrap: anywhere`.

---

## 6. Порядок сборки самому

Если бы писал с нуля, шаги такие:

1. `useState` для `posts`, вывести заголовок.
2. `useEffect` + `fetch`, `setPosts(data)` — убедиться, что данные пришли (`console.log`).
3. `.map()` → карточка, `key={post.id}`.
4. `isLoading` → ранний выход «Загрузка...».
5. `catch` → сообщение об ошибке, проверить, выключив сеть в DevTools.
6. CSS: переменные → сетка → медиазапросы.

---

## Чек-лист принципов

- **Один источник правды** — состояние в App, всё остальное считается из него.
- **Props вниз.** Компоненты-«картиночки» (Header, PostCard) не имеют обратных связей.
- **Производное не хранить** — флаги и производные значения выводятся прямо в рендере.
- **`useEffect` — только когда код должен выполниться «вне рендера»** (запрос при монтировании). Всё остальное здесь решается простым кодом в теле компонента.
- **Зависимости эффекта** — всё, что используется внутри, иначе замыкание «замёрзнет» со старыми значениями. Пустой `[]` = «один раз при старте».
- **`setState` в эффекте — только внутри колбэка** (`.then`), не синхронно в теле.
- **`key` в `.map()` — всегда уникальный id.**
- Проверять работу: `npm run lint`, `npm run build`, и вручную — сеть off, медленный 3G, узкий экран.
